# ez2048

用 Rust 从零写的终端 2048。方向键移动，`Z` 撤回上一步（且不能连续撤回），`Q` 退出；
随机数来自操作系统熵源播种的 CSPRNG，整个程序跑在 `tokio` 异步运行时上。

## 运行

```console
$ cargo run --release
```

需要 Rust 1.85 或更高版本（edition 2024）。终端至少要有 **47 列 × 22 行**，
放不下时会直接提示当前尺寸而不是画出一个错位的棋盘。

## 操作

| 按键 | 作用 |
| --- | --- |
| `↑` `↓` `←` `→` | 朝该方向滑动棋盘 |
| `Z` | 撤回上一步；**不能连续撤回**，撤回后必须先走一步 |
| `R` | 重开一局 |
| `Q` / `Esc` / `Ctrl+C` | 退出 |

规则与标准 2048 一致：同一次滑动中，一个数字只会合并一次，`[2, 2, 2, 2]` 向左只得到
`[4, 4, 0, 0]`；滑不动的方向不消耗步数，也不会重新装填撤回槽。合成出 `2048` 会提示通关，
之后还可以继续冲更高分；棋盘锁死时按 `Z` 依然能退回上一步继续。

## 实现

```
src/
├── main.rs    入口：进入备用屏，用 tokio::select! 驱动主循环
├── board.rs   纯棋盘逻辑：滑动、合并、死局判定
├── game.rs    分数、阶段、以及"只能撤回一步"的撤回槽
├── rng.rs     加密级随机数
├── input.rs   把 crossterm 的阻塞按键事件桥接成异步消息
└── ui.rs      crossterm 绘制
```

### 异步结构

终端读取天生阻塞，所以它被放进 `tokio::task::spawn_blocking` 的 blocking 线程池，
用 `crossterm::event::poll` + `read` 读事件，再通过 `tokio::sync::mpsc` 把语义化的
`Action` 交给主循环。主循环本身是一个 `tokio::select!`：

```rust
tokio::select! {
    biased;
    action = actions.recv() => match action { /* 移动 / 撤回 / 重开 / 退出 */ },
    _ = ticker.tick() => { /* 临时提示消息到点后清掉，必要时重画 */ }
}
```

`biased` 让按键永远优先于定时器，操作手感更跟手；重画只在状态真的变了的时候发生，
不做无谓的刷新。读取任务会在接收端被丢弃后的一个轮询周期内自行退出，所以按 `Q`
退出时不会把进程卡在阻塞读上；`Terminal` 的 `Drop` 负责恢复终端，panic 展开时也会执行。

### 随机数

```rust
let rng = StdRng::try_from_rng(&mut SysRng)?;   // 256 位操作系统熵做种子
let value = if rng.random_ratio(9, 10) { 2 } else { 4 };
```

* `SysRng` 是操作系统熵源（Windows 上走 `ProcessPrng`/`RtlGenRandom` 一类的接口）；
* `StdRng` 是 `rand` 的密码学安全伪随机数发生器，当前实现为 **ChaCha12** 流密码；
* 没用到时间戳、进程号一类的弱种子，`seed_from_u64` 那种不适合加密用途的入口也没用；
* 新数字的位置取自 `rand::seq::IndexedRandom::choose`，是全空格集合上的均匀分布。

### 依赖

| crate | 版本 | 用途 |
| --- | --- | --- |
| [`crossterm`](https://crates.io/crates/crossterm) | 0.29 | 原始模式、备用屏、按键事件、彩色输出、同步更新 |
| [`rand`](https://crates.io/crates/rand) | 0.10 | CSPRNG 与均匀分布取样 |
| [`tokio`](https://crates.io/crates/tokio) | 1.53 | 运行时、blocking 线程池、定时器、mpsc 通道 |
| [`unicode-width`](https://crates.io/crates/unicode-width) | 0.2 | 计算中日韩字符的显示宽度，保证排版对齐 |
| [`anyhow`](https://crates.io/crates/anyhow) | 1.0 | `main` 与各处的错误上下文 |

能交给 crate 的都交给 crate：棋盘外框、光标定位、清行、颜色、按键解析、终端尺寸、
真彩色输出用的都是 `crossterm` 现成的命令，没有自己去拼 ANSI 转义序列；随机取样、
概率判定用的是 `rand` 的 `random_ratio` / `choose`，没有自己写取模或洗牌。

### 绘制

每一帧先在内存里拼成若干行，再放进一次 `SynchronizedUpdate`（DEC 2026）里写出，
终端会把这一批输出当成一次原子刷新，因此不会出现画到一半的画面。每行写之前先
`Clear(UntilNewLine)`，避免上一帧更长的行留下尾巴。标题行按固定显示宽度排版，
所以分数从两位数涨到三位数时整块内容不会左右跳动。

## 测试

```console
$ cargo test
$ cargo clippy --all-targets -- -D warnings
```

28 个单元测试，覆盖：

* **board**：合并只发生一次（`[2,2,2,2] → [4,4,0,0]`）、四个方向的滑动与镜像、得分累计、
  走不动时 `moved == false`、死局判定、空格与最大值统计；
* **game**：连续 400 步的滑动不变量（走不动不算步数、撤回槽只在真正走棋后装填）、
  撤回必须精确还原上一步、**连续撤回被拒绝**、重开清空全部状态、提示消息按时过期；
* **input**：方向键映射、大小写不敏感、按键抬起事件被忽略、`Ctrl+C`、窗口尺寸变化；
* **ui**：整帧行数与宽度、外框与格子带对齐、终端过小时给出提示、双宽度字符的补齐与居中；
* **main**：用脚本化的按键序列跑完整条异步主循环，断言四个方向里至少有一个能走、
  撤回槽就绪、以及第二次连续撤回收到的拒绝提示。

## 限制

* 需要支持 ANSI 转义序列的终端（Windows 10 及以上、Windows Terminal、以及各类
  Unix 终端）。配色用的是真彩色，终端不支持时会回落到近似颜色。
* 没有持久化，关掉就是新的一局。
